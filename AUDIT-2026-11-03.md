# Verification and fixes — 3 November 2026

This pass checked the existing production services, local demo and both Expo applications, with mobile usability as the first priority. It did not deploy to the hosting service or send customer messages.

## Implemented

- Shared mobile styling: readable input sizes, 44-pixel touch targets, keyboard focus, wrapping headings and buttons, bounded dialogs and a reachable save bar. The administrator's user list becomes labelled cards on small screens.
- Expo controls retain their text during loading, use the shared purple palette and fit narrow screens more reliably.
- WhatsApp settings: intent selection starts with a valid value, rule priority is editable, invalid example data is rejected and successful saves are announced.
- Shared reply-rule matching ignores empty keywords and unvalidated legacy regular expressions. Hosted processing can try the next matching rule when the first has reached its cooldown or daily allowance.
- The demo applies saved rules, cooldowns, daily rule allowances, reply delays, tags, sentiment and separate direct/group permissions. Conversations stay in order; waiting approval drafts cannot be silently replaced by later messages.
- Instagram webhooks acknowledge saved events without waiting for model generation. A new message during generation postpones the older draft so it can be answered in context.
- Instagram delivery timeouts and missing receipts remain uncertain through recovery. New inquiries remain visible. The owner must explicitly verify delivery before another reply, generation or resolution; the interface provides those verification actions.
- Instagram provider routing respects approved fallback settings and the shared active provider. Invalid keys and declined requests are reported. Short-lived provider failures remain queued; quota cooldowns and shared fallback changes invalidate stale cached state.
- Adaptive response length is applied to the prompt and output handling. Age review applies even when an adult persona mode is selected. This work changed application controls and prompting; it did not train model weights.
- The private admin overview shows a process-local WhatsApp worker heartbeat, saved queue issues, attempt counts and retry availability. Refresh errors no longer imply a fresh health check.
- Removed private owner branding from a customer WhatsApp connection screen. The customer application has no need to know private owner endpoints.
- Repaired the isolated Instagram test harness to use current authentication, storage and timing behavior. Added one command for both hosted service test suites. Replaced obsolete setup documentation.
- Enabled the demo's Tailwind processing and reused the current shared theme. Removed its CSS workaround that hid an inaccurate AI status; the dashboard now accepts the demo's actual routing explanation.
